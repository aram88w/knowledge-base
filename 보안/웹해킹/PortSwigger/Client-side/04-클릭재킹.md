## 클릭재킹

가짜 웹사이트에 사용자가 눈으로 보는 화면 뒤에 투명한 레이어(`<iframe>` 태그)를 겹쳐두어 의도하지 않은 버튼이나 링크를 클릭하게 만드는 사용자 인터페이스(UI) 수정 공격
`iframe` 안에는 **진짜 사이트 페이지가 정상적으로 로드**되어 있는 것이므로 CSRF 토큰으로 방어할 수 없음. 

예: 해커의 웹사이트에서 상품을 받기 위해 버튼을 클릭하면 사용자는 해커의 의해 숨겨진 버튼을 클릭하게 되어 다른 웹사이트의 결제가 발생함. 


**Clickbandit 도구 (Burp Suite)**
클릭재킹 취약점을 테스트할 때 수동으로 HTML/CSS를 작성하고 좌표를 조정하던 번거로운 과정을 자동화해 주는 도구

1. Burp Suite 상단 메뉴에서 `Burp` → `Burp Clickbandit`를 열기
2. `Copy Clickbandit to clipboard` 버튼을 눌러 스크립트를 복사
3. Burp 브라우저(또는 개발자 도구가 있는 브라우저)에서 테스트할 웹페이지를 열기
4. `F12`로 개발자 도구의 **Console 탭**을 열고, 복사한 스크립트를 붙여넣고 실행
5. 상단에 나타나는 Clickbandit 배너에서 `Start`를 누르고, 공격하고 싶은 버튼들을 순서대로 클릭
6. `Finish`를 누르면 공격 화면이 나타나고, 여기서 **투명도, 위치, 확대/축소** 등을 조절해 완성
7. `Save`를 눌러 HTML 파일로 저장


### 취약점

#### 기본 동작

``` html
<!DOCTYPE html>
<html>
  <head>
    <style>
      #target_website {
          position:relative;
          width:1000px;
          height:700px;
          opacity:0.1;
          z-index:2;
          border:none;
      }
      #decoy_website {
          position:absolute;
          top:520px;  
          left:60px;
          z-index:1;
      }
    </style>
  </head>
  <body>
      <div id="decoy_website">Click me</div>
      <iframe id="target_website" src='https://target.com/my-account'>
  </body>
</html>
```
- `z-index`의 값이 클수록 앞에 위치함. 
- `opacity`의 값은 투명도를 나타냄. (브라우저에서 클릭재킹 공격의 방어를 위해 iframe의 투명도가 특정 값 밑으로 내려가면 클릭이 이벤트를 발생시키지 않음.)


#### 사전 폼 양식 입력 

일부 웹사이트는 폼 제출 전에 GET 요청의 쿼리 파라미터로 폼 입력 필드를 미리 채울 수 있음. 
예: `/my-account?email=...`



#### 프레임 버스팅

클릭재킹 공격은 보통 다른 웹사이트에 프레임되는 경우에 발생함. 그래서 프레임 기능을 제한함으로써 공격을 방어하려고 함. 
- 현재 애플리케이션 창이 최상위 창인지 확인하고, 아니면 최상위 창으로 만듬.
- 모든 프레임을 보이도록 설정
- 보이지 않는 프레임 클릭 방지
- 클릭재킹 가능성을 감지하고 사용자에게 알림.

프레임 버스팅은 두 가지 방식으로 구현 가능함. 
1. **웹사이트 자체 JavaScript로 구현**  
    → 피해 사이트 개발자가 자기 페이지에 넣는 코드  
    → 공격자의 `sandbox`로 무력화 **가능**
    
``` js
// 예시: iframe 안에 있던 사이트가 최상위 창을 자기 자신으로 바꿔서 iframe을 깨고 나오는 코드 
if (top != self) {
    top.location = self.location;
}
```

2. **브라우저 확장 프로그램(예: NoScript)으로 구현**  
    → 사용자가 자기 브라우저에 설치한 확장이 대신 프레임 버스터를 실행하거나, iframe 자체를 차단  
    → 공격자의 `sandbox`로 무력화 **불가능** (브라우저 레벨에서 동작하므로)


**우회**
`iframe`의 `sandbox` 속성을 `allow-forms` 또는 `allow-scripts"`로 설정하면 iframe 내에서 폼 전송과 스크립트 실행은 허용됨. 
그리고 `allow-top-navigation`과 `allow-same-origin`을 생략함으로써 iframe은 최상위 창에 접근할 수 없고, 최상위 창을 이동시킬 수도 없기 때문에 JavaScript로 구현된 프레임 버스터(최상위 창 이동, 부모 DOM 조작, 투명도 확인, 경고 표시 등)가 모두 무력화됨. 

``` html
<iframe id="victim_website" src="https://victim-website.com" sandbox="allow-forms"></iframe>
```


#### DOM XSS 결합

DOM XSS 공격의 수단으로 클릭재킹을 이용할 수 있음. 
예: 폼에서 name 필드에 값이 화면에 `innerHTML`으로 삽입되는 경우 name 필드에 쿼리 파라미터로 악성 스크립트(`<img src=1 onerror=...>`)를 채워두고 클릭재킹을 유도해 폼 제출을 할 수 있음. 

참고: `innerHTML`을 통해 삽입된 `<script>`는 실행되지 않으므로 `img`, `svg`, `iframe`을 이용해야함. 


### 공격 방지 

서버가 브라우저한테 자신의 웹사이트는 iframe으로 불러오지 말라고 **HTTP 응답 헤더에 명시**하고 브라우저 측에서 iframe의 사용을 제한하면 클릭재킹을 방지할 수 있음. (브라우저에서 해당 기능을 지원해야함.)

#### X-Frame-Options

- 해당 웹사이트의 iframe 사용 차단
``` http 
X-Frame-Options: deny
```

- 동일한 출처에서만 사용 가능
``` http 
X-Frame-Options: sameorigin
```

- 특정 웹사이트에서만 허용
``` http
X-Frame-Options: allow-from https://normal-website.com
```

X-Frame-Options는 브라우저마다 지원 여부가 다름. (예: Chrome 76+: `allow-from` 지원 안 함) 따라서 실무에서는 콘텐츠 보안 정책(CSP)를 사용함. 


#### CSP

콘텐츠 보안 정책(Content Security Policy, CSP)는 클릭재킹 및 XSS 공격을 탐지하고 방어하는 보안 메커니즘 

``` css
Content-Security-Policy: 지시어1 출처1 출처2; 지시어2 출처1
```
- HTTP 응답 헤더로 브라우저에게 정책을 전달
- 세미콜론(`;`)으로 정책을 구분


- 해당 웹사이트의 iframe 사용 차단
``` css
Content-Security-Policy: frame-ancestors 'none';
```

- 동일한 출처에서만 사용 가능
``` css 
Content-Security-Policy: frame-ancestors 'self';
```

- 특정 웹사이트에서만 허용
``` css
Content-Security-Policy: frame-ancestors normal-website.com;
```
