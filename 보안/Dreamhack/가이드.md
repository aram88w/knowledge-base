### 문제가 안 풀릴 때

문제가 안 풀리는 기준: 소스코드를 분석했는데 새로운 가설이 나오지 않고 정체된 경우

| 번호 | 도움 유형 | 허용 시점 | 기준 |
|---|---|---|---|
| 1 | 코드 문법·API 검색 | 항상 허용 | 모르는 언어 문법, 함수, 라이브러리 등의 동작 확인 |
| 2 | Obsidian 정리본 탐색 | 조건부 허용 | 문법·기본 원리 확인은 항상 허용, 공격 기법·우회 방법 탐색은 정체된 이후 허용 |
| 3 | AI에게 가설 검증 요청 | 항상 허용 | 직접 세운 가설의 타당성, 코드 동작, 실험 실패 원인 확인. 새로운 공격 방향이나 정답은 요청하지 않음 |
| 4 | 구글에서 취약점 원리·공격 기법 검색 | 정체된 이후 허용 | 구체적인 공격 기법·우회 방법 검색은 정체된 이후 허용 |
| 5 | AI에게 해당 워게임 힌트 요청 | 정체된 이후 허용 | 일반적인 공격 기법을 조사해도 해결되지 않으면 작은 힌트부터 단계적으로 요청 |

### Write-up 작성법

| 구분         | 기준                                       | 예시                                    |
| ---------- | ---------------------------------------- | ------------------------------------- |
| `Self`     | 공격 아이디어를 스스로 발견하고, 검색은 구현을 위한 보조 수단으로 사용 | `fetch` 문법 검색, 파이썬 문법 검색              |
| `Research` | 검색을 통해 새로운 공격 아이디어나 기법을 발견하고 해결          | 파일 업로드 취약점을 검색하다가 PHP 웹쉘 기법을 알게 되어 해결 |
| `AI-Hint`  | AI에게 문제 해결의 핵심 단서를 얻음                    |                                       |
| `Writeup`  | 해당 문제의 풀이를 참고함                           |                                       |
