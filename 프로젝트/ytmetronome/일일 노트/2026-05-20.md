### `t('~')` 이런 구조로 되어있는건 서버에서 렌더링이 안돼요?

- **서버에서도 완벽하게 렌더링됩니다.**
- `next-intl`은 Next.js App Router의 서버 컴포넌트 환경을 위한 `getTranslations` 함수를 제공하므로, 서버 사이드에서 JSON 파일에 있는 번역 텍스트를 읽어와 완성된 HTML 형태로 브라우저와 검색 엔진 봇에 전달할 수 있습니다.
- 다만 마크다운에 들어있는 볼드체(`**`), 헤더(`###`), 줄바꿈(`\n`) 등의 서식 태그들을 단순 JSON 문자열로 불러올 경우, 이를 브라우저가 해석할 수 있는 HTML 태그로 변환(파싱)하는 추가적인 작업이 여전히 필요합니다.


### SSR이 아닌경우에 SEO가 못 읽나요?

- **일부는 읽을 수 있지만, 성능과 수집률에서 손해를 봅니다.**
- **구글봇(Googlebot)** 처럼 고도화된 검색 엔진 봇은 자바스크립트를 실행할 수 있는 브라우저 엔진을 탑재하고 있어, 클라이언트 사이드 렌더링(CSR)으로 그려지는 콘텐츠도 최종적으로는 읽을 수 있습니다.
- 그러나 **네이버(Yeti), 다음(Daumoa)**, 그리고 카카오톡·페이스북 등 링크 공유 시 미리보기를 긁어가는 **소셜 미디어 봇(OG Bot)**들은 자바스크립트를 실행하지 못하는 경우가 많아, 초기 HTML 소스에 글이 적혀있지 않으면 아예 읽지 못합니다.
- 또한 구글봇조차도 자바스크립트 실행이 필요한 페이지(CSR)는 렌더링 큐(Queue)에 대기시킨 후 2차로 분석하기 때문에, **색인(인덱싱) 속도가 느려지고 검색 노출 경쟁에서 SSR 페이지보다 다소 불리해집니다.**
- 따라서 검색 엔진 최적화(SEO)의 효과를 온전히 보려면 초기 HTML에 텍스트가 완전히 찍혀서 나가는 **SSR(서버 사이드 렌더링)** 방식으로 구현하는 것이 가장 강력하고 안전합니다.

### 클라이언트 컴포넌트(`"use client"`)는 서버에서 아예 렌더링을 하지 않는 건가요?

- **아닙니다. 클라이언트 컴포넌트도 서버에서 최초 1회 정적 HTML로 렌더링(Pre-rendering)됩니다.**
- Next.js에서 `"use client"`는 *"이 컴포넌트는 오직 클라이언트에서만 렌더링하라"* 는 뜻이 아닙니다. 실제 의미는 **"이 컴포넌트는 브라우저(클라이언트)에 전달되어 상태 관리(useState), 이벤트 리스너(onClick), 브라우저 API 등을 사용하는 인터랙티브한 컴포넌트의 경계선이다"** 라는 선언에 가깝습니다.
- 따라서 서버는 최초 요청 시 클라이언트 컴포넌트 내부에 적힌 정적 텍스트나 UI 구조까지 **모두 포함하여 HTML을 렌더링한 후 브라우저에 전달**합니다.
- 덕분에 사용자와 검색 엔진 봇은 자바스크립트가 실행되기 전에도 클라이언트 컴포넌트의 초기 모습과 텍스트를 즉시 볼 수 있으며, 이로 인해 기본적인 SEO도 정상 작동합니다.

##### 💡 주의할 점 (클라이언트 컴포넌트와 SEO)

- 다만 클라이언트 컴포넌트 내부에서 `useState`나 `useEffect`를 통해 **클라이언트 측에서 동적으로 데이터를 받아와서 띄우는 텍스트**는 서버가 최초 HTML을 만들 때 포함할 수 없습니다. (예: `window` 객체에 접근하여 가져온 데이터나 클라이언트 사이드 `fetch` 데이터 등)
- 하지만 단순히 JSON 다국어 데이터를 컴포넌트 초기에 띄우는 것이나, 컴포넌트 구조 내부에 직접 텍스트를 적어두는 수준이라면 `"use client"` 컴포넌트 내부의 글자들도 서버에서 렌더링되어 HTML에 포함되므로 검색 엔진이 완벽하게 읽어갑니다.


### 사이트맵

##### 1. 사이트맵 엔트리에 들어가는 핵심 정보

각 페이지 경로마다 다음과 같은 정보를 지정합니다:

- **`url`**: 페이지의 절대 경로 URL (예: `https://ytmetronome.com/ko`)
- **`lastModified`**: 해당 페이지가 마지막으로 수정된 날짜 (보통 `new Date()`를 사용)
- **`changeFrequency`**: 페이지 내용이 얼마나 자주 바뀌는지에 대한 힌트 (`daily`, `weekly`, `monthly` 등)
- **`priority`**: 전체 사이트 내에서 해당 페이지의 상대적 중요도 (`0.0` ~ `1.0`)

---

##### 2. 다국어 지원 사이트맵 작성 방법 (i18n 대응)

현재 프로젝트는 `[locale]` 동적 라우팅 방식을 사용하고 있으며, 지원하는 언어는 총 8개(`ko`, `en`, `de`, `es`, `fr`, `ja`, `pt`, `zh`)입니다.

이를 고려하여 `app/sitemap.ts` 파일을 작성할 때 아래와 같이 각 언어별 경로를 배열로 동적 혹은 정적으로 생성하여 반환하면 됩니다.

``` ts
import { MetadataRoute } from 'next'

// 지원하는 언어 목록 정의
const locales = ['ko', 'en', 'de', 'es', 'fr', 'ja', 'pt', 'zh']
const BASE_URL = 'https://ytmetronome.com'

export default function sitemap(): MetadataRoute.Sitemap {
  // 1. 기본 루트 경로 (https://ytmetronome.com)
  const rootSitemap = {
    url: BASE_URL,
    lastModified: new Date(),
    changeFrequency: 'weekly' as const,
    priority: 1.0,
  }

  // 2. 각 언어별 경로 (https://ytmetronome.com/ko, /en 등)
  const localeSitemaps = locales.map((locale) => ({
    url: `${BASE_URL}/${locale}`,
    lastModified: new Date(),
    changeFrequency: 'weekly' as const,
    // 메인 루트보다는 우선순위를 조금 낮게 설정 (예: 0.8)
    priority: 0.8, 
  }))

  return [rootSitemap, ...localeSitemaps]
}

```
