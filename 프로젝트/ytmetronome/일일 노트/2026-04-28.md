**"하위 계층에서는 에러를 던지기만 하고(Throw), 최상위 계층(또는 적절한 진입점)에서 한 번에 잡아(Catch) 처리하는 것"**이 모던 소프트웨어 아키텍처의 핵심 원칙 중 하나인 **"중앙 집중식 에러 핸들링(Centralized Error Handling)"**입니다.

actions.ts에서 에러를 콘솔에 찍고 다시 던져서 컴포넌트에서 에러처리를 하는 아키텍처가 흔함.

StreamURL에서 1MB만 다운 받은 후 작업
1. **압축된 상태 (MP3, M4A)**: 우리가 유튜브에서 다운받는 오디오는 용량을 줄이기 위해 고도로 압축되어 있습니다. 사람이 들을 때는 오디오 플레이어가 알아서 실시간으로 압축을 풀어서 들려주지만, 컴퓨터(Essentia.js)가 수학적으로 분석하기에는 **알아볼 수 없는 암호 덩어리**일 뿐입니다.
2. **ArrayBuffer (순수 데이터 가져오기)**: 네트워크(`fetch`)를 통해 가져온 데이터를 일단 자바스크립트가 만질 수 있는 순수한 바이트(Byte) 덩어리 상태인 `ArrayBuffer`로 메모리에 올려놓습니다. (알집 파일을 다운로드 완료한 상태)
3. **디코딩 (decodeAudioData)**: 이제 브라우저의 오디오 엔진(`AudioContext`)을 시켜서 이 암호화된 바이트 덩어리의 **압축을 풉니다.** (알집 압축 풀기) 압축을 풀면 나오는 것이 바로 **PCM 데이터(Float32Array)**입니다.
4. **결과물 (Float32Array)**: 이 데이터는 1초에 44,100개의 숫자(소리의 파형, 진폭)들이 쫙 나열된 거대한 숫자 배열입니다. **Essentia.js는 바로 이 숫자들을 보면서 "아! 소리가 여기서 커지는구나(비트구나)!" 하고 분석할 수 있습니다.**


Next.js에서 Essentia.js를 사용할때 발생하는 문제 
Essentia.js는 Node.js 전용 모듈(fs, 파일 시스템)을 사용하는 코드가 있는데 그걸 브라우저 환경에서 불러오려고 해서 에러가 발생함.
