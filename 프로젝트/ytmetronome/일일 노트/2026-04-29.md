Essentia.js를 Next.js에서 사용할때 발생하는 까다로운 설정 에러가 있음. 이건 그냥 가져다 써야할 것 같음.

AudioContext 등의 작업은 어디서 처리되나요? (메인 스레드? 워커?)
**결론부터 말씀드리면, 브라우저 내부의 '별도 오디오 스레드(Audio Thread)'에서 처리됩니다.**

압축을 푼 오디오 파일은 브라우저 메모리에 저장되나요?
**브라우저의 메모리(RAM)에 저장**, 여기서 한 가지 중요한 점은, 압축된 `arrayBuffer`가 1MB라고 할지라도 디코딩을 거쳐 압축이 풀린 파형 데이터(`AudioBuffer`)가 되면 **메모리 차지 용량이 10배~20배 가까이 뻥튀기**된다는 점입니다. (마치 1MB짜리 zip 파일을 풀었더니 10MB짜리 텍스트 파일이 나오는 것과 같습니다.) 함수 실행이 끝나고 오디오 분석이 완료되면, 자바스크립트의 가비지 컬렉터(Garbage Collector)가 이 거대한 데이터들을 메모리에서 알아서 청소(삭제)해 줍니다.

Essentia.js 작업은 **'메인 스레드(Main Thread)'** 에서 실행됩니다.

Essentia.js로 추출한 bpm이 음원의 오차인지 Essentia.js의 오차인지 알 수가 없음. 

참고: `!= null`을 사용하면 `null`과 `undefined`를 둘 다 걸러주면서 `0`은 통과시킵니다.

간단히 요약하면 **`: Type` (타입 선언)은 "검사해줘"** 이고, **`as Type` (타입 단언)은 "내 말을 믿어"** 입니다.
- **일반적인 변수나 객체를 만들 때:** 항상 **`: Type` (타입 선언)** 을 사용하여 TS가 꼼꼼하게 검사하게 만듭니다.
- **외부 API 통신 (`fetch`, `JSON.parse` 등) 결과:** 어차피 TS가 검사할 수 없는 `any`나 `unknown`이 들어오는 곳이므로, 개발자가 책임을 지고 모양을 씌워준다는 의미를 강조하기 위해 **`as Type` (타입 단언)** 을 관습적으로 많이 사용합니다.

외부 API 통신을 할 때는 이렇게 **"내가 받을 데이터의 규격(Interface)을 만들고, `as`로 덮어씌운다"** 라고 생각하시면 Spring에서의 DTO 매핑과 거의 똑같은 감각으로 개발하실 수 있습니다!
``` ts
// lib/api.ts 상단에 정의
interface YouTubeApiResponse {
    error: boolean;
    message?: string; // 에러 메시지는 에러가 났을 때만 있을 수 있으므로 옵셔널(?) 처리
    linkDownload: string;
    title: string;
    // 그 외 videoId, lengthSeconds 등은 당장 안 쓰니까 생략해도 무방합니다.
}
```
