### 메타데이터는 각 페이지별로 지정할 수 있는가? `layout.tsx`와 각 `page.tsx`들의 관계는?

**네, 각 페이지별로 개별 지정(재정의)하는 것이 강력히 권장됩니다.**

- **작동 원리 (상속과 덮어쓰기)**
    - Next.js에서 `layout.tsx`에 지정한 메타데이터는 **'기본값(Default)'** 역할을 합니다.
    - 하위 폴더의 `page.tsx`에 메타데이터를 지정하지 않으면 `layout.tsx`의 메타데이터를 그대로 물려받습니다.
    - 하지만 하위 `page.tsx`에서 메타데이터를 정의하면, **해당 페이지에 한해 `layout.tsx`에 있던 메타데이터가 덮어써집니다(Override).**
- **권장하는 적용 방식**
    - **`app/[locale]/page.tsx` (메인 페이지)**: 메인 페이지는 사이트의 가장 핵심적인 얼굴이므로 메인용 키워드가 들어간 메타데이터를 직접 선언하는 것이 좋습니다. (`layout.tsx`에는 전역 설정(파비콘, 기본 오픈그래프 설정 등)만 남겨두고, 실제 타이틀과 설명은 메인 `page.tsx`에서 정의하는 방식이 표준적입니다.)
    - **`terms/page.tsx` 및 `privacy/page.tsx`**: 네, 반드시 각각 지정해 주어야 합니다. 그렇지 않으면 구글 검색 결과에 이용약관 페이지의 제목이 메인 페이지 제목("YT Metronome - 유튜브 연동 온라인 메트로놈")과 동일하게 나와 중복 타이틀 오류가 발생합니다. 이곳에는 `<title>이용약관 - YT Metronome</title>`과 같이 깔끔하게 덮어써 주어야 합니다.

### 캐노니컬 태그(Canonical Link)는 어차피 페이지가 하나인데도 유의미한가?

**네, 페이지가 하나이더라도 매우 유의미하며 현대 SEO에서는 필수적입니다.**

- **이유 1: URL 파라미터로 인한 중복 처리 방지**
    - 사용자가 SNS에 공유하거나 광고를 집행할 때, URL 뒤에 추적 코드 파라미터가 붙는 경우가 많습니다 (예: `https://ytmetronome.com/ko/tempo/60?utm_source=facebook&fbclid=xxxx`).
    - 구글 검색 로봇은 주소창의 파라미터가 다르면 이를 **서로 다른 페이지**로 인식할 수 있습니다. 이때 캐노니컬 태그가 지정되어 있으면 "파라미터가 무엇이든 이 페이지의 진짜 원본 주소는 `https://ytmetronome.com/ko/tempo/60` 이다"라고 검색 로봇에 명시적으로 알려주어 SEO 점수가 분산되는 것을 막아줍니다.
- **이유 2: 주소 표기 차이 통일**
    - `http`와 `https`, `www`가 붙은 주소와 안 붙은 주소, 슬래시가 붙은 것과 안 붙은 것(`.../60` vs `.../60/`) 등의 미세한 차이를 하나의 원본 URL로 단일화해 줍니다.


### 공통 메타데이터 설정

``` tsx
// app/layout.tsx
import { Metadata } from 'next';
 
export const metadata: Metadata = {
  title: {
    template: '%s | Acme Dashboard',
    default: 'Acme Dashboard',
  },
  description: 'The official Next.js Learn Dashboard built with App Router.',
  metadataBase: new URL('https://next-learn-dashboard.vercel.sh'),
};
```

``` tsx
// app/dashboard/invoices/page.tsx
export const metadata: Metadata = {
  title: 'Invoices',
};
```

페이지로 이동하여 `<head>` 요소를 확인하세요. 페이지 제목이 이제 `Invoices | Acme Dashboard` 로 표시되어야 합니다.


### SEO, 다국어의 순서를 어떻게 해야할지

SEO를 추가할수록 다국어가 계속 추가되고 xx.json에 문장을 추가하면서 진행하니까 속도가 느려짐.


### generateStaticParams

동적 라우트 `[slug]`에 대해 **"어떤 slug 값들이 존재하는지"** 미리 알려주는 함수예요.

``` tsx
// 빌드 시 Next.js에게 "이 12개 경로가 존재한다"고 알려줌
export function generateStaticParams() {
  return [
    { slug: "60-bpm-metronome" },
    { slug: "70-bpm-metronome" },
    { slug: "80-bpm-metronome" },
    // ... 나머지
  ];
}
```

##### 있을 때 vs 없을 때

||**있을 때**|**없을 때**|
|**빌드 시**|12개 HTML 미리 생성|아무것도 생성 안 함|
|**첫 방문**|즉시 응답 (이미 만들어진 HTML)|서버에서 그 때 렌더링 (약간 느림)|
|**SEO**|크롤러가 바로 읽을 수 있음|크롤러 접근 시 SSR 필요|

BPM 목록이 고정(12개)이고 자주 바뀌지 않으니까 `generateStaticParams`로 미리 생성하는 게 성능 + SEO 모두에 유리합니다. 없어도 동작은 하지만, 있으면 더 빠르게 응답됩니다.


`[locale]` 동적 세그먼트에 대해서는 보통 **layout.tsx 레벨**에서 한 번만 정의하면 하위 모든 페이지에 적용됩니다.
하지만 **next-intl 미들웨어**가 이미 locale 라우팅을 처리하고 있어서, 없어도 동작에는 문제없습니다. `page.tsx` 자체에는 `[locale]` 외에 다른 동적 세그먼트가 없으니 `generateStaticParams`가 필요 없어요.


### 페이지별로 메인 키워드를 다르게 하는 것이 맞아? 

질문하신 부분은 SEO(검색 엔진 최적화) 전략 수립 시 매우 중요하게 다루어지는 부분입니다. 결론부터 말씀드리면, **메인 페이지와 BPM별 상세(Tempo) 페이지의 H1/Title 키워드를 다르게 가져가는 것이 크게 득이 됩니다.**

##### 1. 키워드 자기잠식(Keyword Cannibalization) 방지

모든 서브 페이지(60~200 BPM)가 메인 페이지와 동일하게 `유튜브 연동 온라인 메트로놈`이라는 키워드만 밀게 되면, 검색엔진(구글, 네이버 등)은 **"이 사이트에서 '유튜브 연동 메트로놈'을 검색한 사용자에게 보여줄 가장 적절한 페이지가 어디인지"** 혼란을 겪게 됩니다. 결과적으로 메인 페이지의 노출 순위마저 깎아 먹는 결과(자기잠식)를 낳을 수 있습니다.

##### 2. 검색 의도(Search Intent)의 차이

- **메인 페이지 타겟 유저**: '유튜브 노래에 맞추는 메트로놈'이나 전체적인 메트로놈 서비스 브랜드를 찾는 유저 (`유튜브 메트로놈`, `유튜브 연동 메트로놈` 등)
- **BPM 페이지 타겟 유저**: 특정 템포에서 단순히 악기나 가창 연습을 하기 위해 들어오는 유저 (`200 BPM 메트로놈`, `박자 연습 프로그램`, `온라인 박자 연습기` 등)

200 BPM 페이지를 검색해 들어오는 유저는 처음부터 유튜브 연동 기능을 기대하기보다는 **"빠른 템포 연습용 도구"**를 찾고 있을 확률이 매우 높습니다. 따라서 이들에게는 `온라인 박자 연습 프로그램`이나 `무료 박자 연습` 같은 키워드를 H1/Title에 매칭시켜 주는 것이 검색 결과 노출 및 클릭률(CTR) 향상에 훨씬 유리합니다.

##### 3. 노출 가능한 롱테일 키워드 파이의 확장

모든 페이지의 테마를 다르게 분산시키면 사이트 전체가 가져갈 수 있는 키워드 그물의 영역이 훨씬 넓어집니다.
- **메인**: `유튜브 연동 메트로놈`
- **BPM 서브 페이지들**: `60 BPM 박자 연습`, `120 BPM 온라인 메트로놈`, `무료 박자 연습 프로그램` 등


따라서 지금처럼 메인에서는 독보적인 셀링 포인트인 **유튜브 연동**을 메인으로 밀고, 각 BPM 상세 페이지에서는 **특정 템포별 연습 및 범용적인 온라인 박자 연습 도구**로서의 키워드를 밀어 타겟층을 다원화하는 구조가 가장 정석적이고 효과적인 SEO 전략입니다.
