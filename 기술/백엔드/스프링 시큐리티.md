##### 1,2장
**DelegatingFilterProxy** 객체가 서블릿 필터 체인 중간에 위치해 애플리케이션 컨텍스트에에서 시큐리티 필터 체인을 찾아서 전달

시큐리티 필터 체인 중 **UsernamePasswordAuthenticationFilter**, **BasicAuthenticationFilter** 둘 중 하나라도 사용자 인증을 받으면 요청이 전달됨

curl의 -u 옵션은 HTTP 요청 헤더에 "{username}:{password}" 문자열을 Base64 방법으로 인코딩해 Authorization 헤더에 담아서 전달함

##### 3장: 스프링 시큐리티 인증 아키텍처
**Authentication 인스턴스**: 인증에 필요한 정보나 인증 완료된 정보를 담고 컴포넌트들이 주고받는 메세지 역할, 여러 가지 객체 타입이 있고 객체 타입에 따라 인증 방식이 결정됨

시큐리티 컨텍스트: 인증이 완료된 Authentication 인스턴스를 보관,제공

인증 매니저 **ProviderManager**: 현재 요청에 적합한 인증 방법을 찾아 연결해주는 역할
인증 제공자 **AuthenticationProvider**: 각자 자신이 구현한 인증 방법을 사용해 인증 작업을 수행

**SecurityContextHolder**는 SecurityContextHolderStrategy 인스턴스를 통해 시큐리티 컨텍스트를 보관함. 시큐리티 컨텍스트 보관 전략(SecurityContextHolderStrategy)을 애플리케이션 설정에 설정 가능
**SecurityContextHolderStrategy**은 스레드로컬을 사용하여 시큐리티 컨텍스트를 스레드별로 갖도록 함
- 스레드 로컬 모드: ThreadLocalSecurityContextHolderStrategy
- 상속 가능한 스레드 로컬 모드: InheritableThreadLocalSecurityContextHolderStrategy
- 전역 모드: GlobalSecurityContextHolderStrategy

_SecurityContextHolder > SecurityContextHolderStrategy > 시큐리티 컨텍스트 > Authentication_
SecurityContextHolder는 내부에서 정적 변수로 SecurityContextHolderStrategy를 갖고 있지만 SecurityContextHolderStrategy는 내부에서 스레드로컬을 활용해서 시큐리티 컨텍스트를 관리하기 때문에 정적 변수로 SecurityContextHolderStrategy로 접근해서 시큐리티 컨텍스트를 가져와도 스레드별로 분리 되어있음

**AbstractAuthenticationProcessingFilter**: 사용자 인증의 시작점. 인증에 대한 전반적인 실행 흐름이 정의되어있고 인증에 필요한 정보를 담은 Authentication 인스턴스를 만듬 
템플릿메서드 패턴으로 UsernamePasswordAuthenticationFilter, OAuth2LoginAuthenticationFilter를 호출해서 실제 인증 작업은 해당 클래스에 정의된 방식을 사용
- **UsernamePasswordAuthenticationFilter**: 아이디와 비밀번호로 사용
- **OAuth2LoginAuthenticationFilter**: OAuth 2.0 프로토콜 사용해 외부 서비스와 통신을 통한 인증

AbstractAuthenticationProcessingFilter에서 인증에 성공하면 **AuthenticationSuccessHandler**에서 성공처리, **AuthenticationFailureHandler**에서 실패처리

##### 4장: 폼 로그인 인증
**DefalutLoginPageGeneratingFilter**: 기본 로그인 페이지 제공. 다음 조건인 경우 로그인 페이지 반환
- 로그인 경로(/login)로 GET 요청
- 에러 발생 후 리다이렉트된 요청
- 로그아웃 성공 후 리다이렉트된 요청
**DefalutLogoutPageGeneratingFilter**: 기본 로그아웃 페이지 제공. 다음 조건인 경우 로그아웃 페이지 반환
- 로그아웃 경로(/logout)로 GET 요청

폼 로그인 사용자 인증 프로세스
1. **UsernamePasswordAuthenticationFilter**가 **UsernamePasswordAuthenticationToken** 객체에 인증에 필요한 정보를 담아 ProviderManager에 전달
2. **ProviderManager**는 UsernamePasswordAuthenticationToken을 담당하는 DaoAuthenticationProvider에 전달
3. **DaoAuthenticationProvider**는 **UserDetailService**를 이용해서 사용자 정보 조회해서 인증 작업 수행

**AbstractUserDetailsAuthenticationProvider**: 인증 작업을 지원하는지 판단하고 인증 작업을 수행
**DaoAuthenticationProvider**: AbstractUserDetailsAuthenticationProvider를 구현해서 인증 작업을 정의함. 
1. UserDetailsService를 사용하여 사용자 정보를 조회
2. 조회한 사용자 정보가 유효한지 확인
3. 조회한 사용자 정보의 자격 증명과 요청을 통해 받은 자격 증명을 비교
4. 자격 증명이 올바른 경우 추가적인 상태 확인 (자격 증명의 만료 여부 체크)
5. 새로운 **UsernamePasswordAuthenticationToken** 생성 후 반환

**UserDetailsService**: 사용자 정보를 찾아 UserDetails 인스턴스에 담아 반환
- InMemoryUserDetailsManager: 메모리에 저장된 사용자 정보 조회
- JdbcUserDetailsManager: 관계형 DB에 저장된 사용자 정보 조회
- CachingUserDetailsService: 조회한 사용자 정보를 캐시에 저장하고 재사용, 캐시에 없는 경우 다른 UserDetailsService 사용자 조회에 위임

**PasswordEncoder**: 스프링 시큐리티에서 사용하는 단방향 암호화 인스턴스
- NoOpPasswordEncoder
- BCryptPasswordEncoder
- Argon2PasswordEncoder
- Pbkdf2PasswordEncoder
- SCryptPasswordEncoder
- DelegatingPasswordEncoder
