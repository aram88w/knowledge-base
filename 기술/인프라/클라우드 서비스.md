# Cloudflare

### R2

R2와 연동하기 위해서는 다음의 정보들이 필요함. 
1. S3 API URL (endpoint)
	- 계정 생성 시 이미 부여됨 
	- *버킷 클릭 > 설정*
2. Access Key, Secret Key
	- *Account Details > Manage > 계정 API 토큰 생성* 
	- 권한 설정 및 버킷 등을 지정할 수 있음. 
3. 버킷
	- 사용자 설정 도메인: 공개적인(Public) R2 버킷 설정. 도메인을 연결해서 public-url을 설정할 수 있음. 예: cdn.extractframe.org
	- CORS 정책 설정
	``` 
		[
		  {
		    "AllowedOrigins": [
		      "https://extractframe.org",
		      "https://www.extractframe.org"
		    ],
		    "AllowedMethods": [
		      "GET",
		      "HEAD"
		    ],
		    "AllowedHeaders": [
		      "*"
		    ],
		    "ExposeHeaders": [],
		    "MaxAgeSeconds": 3600
		  }
		]
	```

### Tunnel

- 서버와 외부 인터넷 사이에서 안전하고 암호화된 비밀 통로인 **Cloudflare Tunnel**을 둬서 이 통로를 통해서 요청이 들어오도록 함.
- 장점 
	1. **포트 개방 불필요:** 방화벽에서 80이나 443 포트를 열 필요가 없음. (보안상 엄청난 이점)
	2. **공인 IP 몰라도 됨:** 내 컴퓨터가 카페 와이파이를 쓰든, 집 주소가 바뀌든 상관없음. 터널만 연결되어 있으면 도메인 접속이 유지됨.
	3. **Zero Trust 보안:** 특정 사람만 접속하게 하거나, 구글 로그인을 해야만 내 서버에 들어오게 하는 등의 강력한 보안 설정을 간단하게 가능
	4. **도커 친화적:** 도커 컨테이너 하나로 띄우기만 하면 되므로 관리가 매우 편함.

##### 작동 방식

0. Cloudflare Tunnel 생성: *Zero Trust > 네트워크 > 커넥터*
	- 커넥터 설치 및 실행 파트에서 해당 터널과 통신할 수 있는 cloudflared의 **TUNNEL_TOKEN**을 줌.

1. Cloudflare Tunnel에 도메인 등록 및 응용프로그램 연결
	- 호스트 이름: 도메인 등록 
		- 예: extractframe.org, dozzle.extractframe.org
	- 서비스: 해당 도메인과 연결할 서비스 (도커 서비스 이름 사용)
		- 예: HTTP capture-frontend:80, HTTP dozzle:8080

2. 도커에 cloudflared 컨테이너 설정
	``` yml
	cloudflared:
		image: cloudflare/cloudflared:latest
		container_name: cloudflared
		restart: unless-stopped
		command: tunnel run
		# 도커 네트워크 설정으로 Nginx(리버스프록시)만 연결되게 하고 DB, Redis, 백엔드는 직접 접근하지 못하도록 함. 
		networks:
			- frontend-network 
		environment:
			- TUNNEL_TOKEN=${TUNNEL_TOKEN:-} # Tunnel을 만들때 발급받은 토큰 사용
	```
	- 서버에서 Cloudflare Tunnel과 통신을 할 cloudflared 프로그램을 설치해야함. 
	- cloudflared가 Cloudflare 서버로 **아웃바운드** 연결을 시도하기 때문에 서버에서 인바운드 포트를 모두 닫아놔도 서비스가 가능
	- 서버의 cloudflared가 Cloudflare Tunnel에 연결을 요청하는 것이기에 서버의 IP가 고정이 아니어도 상관없음. 

3. 요청이 들어오면 Cloudflare Tunnel이 WAF(방화벽)나 DDos 방어 등이 먼저 작동하고 깨끗한 요청만 터널로 보내줌. 
4. cloudflared는 내부에서 다른 서비스와 통신함.


##### 엑세스 제어 

- 특정 경로에 대해서 인증 절차를 만들 수 있음. 

1. 정책 등록
	- *엑세스 제어 > 정책*
	- 이메일 인증, IP 등 다양한 규칙 추가 가능
2. 응용 프로그램 추가 
	- *엑세스 제어 > 응용 프로그램*
	- 인증이 필요한 응용 프로그램 지정 (Tunnel에 등록한 도메인 중)
3. 정책 추가: 1번에서 등록한 정책이나 새 정책을 만들어서 등록


### 도메인

##### DNS 레코드

- DNS에 경로와 IP나 서비스 위치로 연결해주는 레코드를 등록
- 레코드 등록 
	1. 형식
		- A: 도메인을 IPv4 주소에 직접 연결
		- CNAME: 도메인을 다른 도메인 이름으로 연결
		- TXT: 도메인에 텍스트 메모를 저장 (Google Search Console 연결)
	2. 이름: 경로명 
		- 예: www로 등록하면 www.도메인 으로 자동 등록됨. 
	3. 콘텐츠: 찾아갈 IP나 서비스 위치
		- Cloudflare Tunnel로 연결할 경우: 터널 ID를 입력해야함. 
			- *Cloudflare Tunnel 고유 ID: Zero Trust > 네트워크 > 커넥터 > 터널 > 터널 ID*
		- Cloudflare Pages로 연결할 경우: Cloudflare Pages가 생성하는 기본 도메인 입력 (프로젝트명.pages.dev)
			- *컴퓨트 > Workers 및 Pages > 해당 Pages*

- **예시 (Cloudflare Tunnel 사용)**
	1. 형식: CNAME, 이름: extractframe.org, 대상: 터널 ID로 등록
	2. extractframe.org로 접속시 DNS 서버에서 터널 ID로 연결해줌 
	3. 터널 ID에서는 서버에 등록해둔 cloudflared와 통신을 하기 때문에 서버에서 extractframe.org의 응답 결과를 내려줄 수 있음.

- WWW에서 루트로 리다이렉트 설정
	1. DNS 레코드 추가: www.extractframe.org로 요청시 extractframe.org를 찾아가도록 해줌. 
		- 형식: CNAME, 이름: www, 대상: extractframe.org
	2. 규칙 추가: www.extractframe.org를 extractframe.org로 리다이렉트 해줌.
		- 요청 URL: https://www.extractframe.org/* 
		- 대상 URL: https://extractframe.org/${1}

##### 보안 

1. 설정: 다양한 보안 관련 설정을 껐다 켰다 할 수 있음.
2. 보안 규칙 설정: 
	- 직접 특정 IP를 차단하거나 특정 파일로의 접근 막는다거나 지속적인 요청을 막는다거나 커스텀 보안설정을 할 수 있음.
	- **사용자 지정 규칙**: 악성 트래픽으로부터 웹 사이트 및 API를 보호
		- 예: .env, config.php, wp-login 등 접근하면 안되는 파일 경로 차단
	- **속도 제한 규칙**: 악의적인 트래픽으로부터 웹 사이트 및 API를 보호
		- 예: 10초 동안 100번 요청 이상이면 차단


# GCP 

##### e2-micro

CPU 2코어, 메모리 1기가

1. e2-micro 인스턴스 생성 
	- *Google Cloud > Compute Engine > VM 인스턴스*
	- e2-micro 스펙에 맞춰서 인스턴스 생성

2. SSH 접속 도커 다운로드 
	``` bash
	curl -fsSL https://get.docker.com -o get-docker.sh
	sudo sh get-docker.sh
	sudo usermod -aG docker $USER # sudo 없이 도커를 사용 할 수 있도록 권한을 줌. 
	# 이후 터미널 재접속 필요
	```

3. `docker-compose.yml` 파일 가져오기
	- Git 사용 (추천): 프로젝트를 GitHub에 올렸다면 `git clone`으로 통째로 가져옴.
	- SCP/SFTP: 내 컴퓨터에 있는 파일을 `gcloud compute scp` 명령어나 파일 전송 툴로 직접 복사
	- 구글 SSH에서 제공하는 업로드 기능

4. Swap 메모리 설정: e2-micro의 램은 1GB라서 디스크의 일부를 메모리처럼 쓰는 Swap 메모리 설정이 거의 필수임.
	``` bash
	# 2GB 스왑 파일 생성 예시
	sudo fallocate -l 2G /swapfile
	sudo chmod 600 /swapfile
	sudo mkswap /swapfile
	sudo swapon /swapfile
	```

5. GCP 방화벽 설정
	- 구글 클라우드 입구에서 포트를 열어둬야함. (http: 80, https: 443)
	- e2 인스턴스를 만들 때 **HTTP 트래픽 허용**, **HTTPS 트래픽 허용**을 체크하면 자동으로 80/443 포트가 열려있음.
	- Cloudflare Tunnel을 사용하는 경우에는 설정할 필요 없음. 
		- 방화벽은 인바운드(수신) 규칙인데 Cloudflare Tunnel은 cloudflared가 Cloudflare로 통신을 시도하는 **아웃바운드 방식**임. 

6. 실행: `docker-compose up -d`


##### Cloud Run 

- *Google Cloud > Cloud Run*
- 저장소에서 지속적 배포를 선택하고 GitHub와 연동하면 `git push`만으로도 빌드, 배포가 자동으로 됨.
- 내 서버에서만 호출되도록 하려면 **IAM 인증 설정**을 하면 됨.
	1. Cloudf Run에서 인증 필요 > IAM 설정
	2. IAM에서 **Cloud Run 호출자 권한**을 가진 구성원 생성
	3. 서버에서 Cloud Run에 호출을 보낼때 헤더에 **ID 토큰**을 같이 보냄. 
		- 서버를 GCP를 사용한다면 별도의 인증 없이 ID 토큰을 발급 받을 수 있음.
		- 다른 서버를 사용중이라면 구글 콘솔에서 생성한 '서비스 계정 키 파일(JSON)'을 서버에 다운받고, 환경 변수로 그 위치를 지정 한 후 ID 토큰 발급 받아야함. 


# GitHub Actions

##### CI/CD 파이프라인

- GitHub Actions 워크플로우를 통해서 `git push`만 하면 빌드, 배포까지 자동으로 처리되도록 함. 
- 작동 방식
	1. GitHub Actions에서 빌드 후 GHCR에 이미지 저장
	2. 서버에 SSH 접속해서 GHCR에 접근해서 이미지로 배포 

``` yml
name: Frontend Build & Push & Deploy

# main 브랜치에 코드가 push 될 때마다 실행됨. 
on:
  push:
    branches: [ "main" ]

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest # GitHub이 제공하는 무료 리눅스 서버
    permissions: # 권한 설정 (읽기, 쓰기)
      contents: read
      packages: write

    steps:
	    # GitHub 서버로 현재 소스 코드를 내려 받음.
      - name: 1. 저장소 코드 체크아웃
        uses: actions/checkout@v4

		# GHCR에 로그인, GITHUB_TOKEN은 별도 설정 없이도 GitHub에서 자동 제공
      - name: 2. GHCR 로그인
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: 3. Docker 이미지 빌드 및 푸시
        # Docker 이미지 태그는 소문자여야 하므로 GitHub 저장소 이름을 소문자로 변환
        run: |
          REPO_LOWER=$(echo "${{ github.repository }}" | tr '[:upper:]' '[:lower:]')
          docker build -t ghcr.io/$REPO_LOWER:latest .
          docker push ghcr.io/$REPO_LOWER:latest

		# e2-micro에 SSH 연결로 배포 명령어 실행
      - name: 4. GCP e2-micro 자동 배포 (SSH CD)
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.GCP_HOST }}
          username: ${{ secrets.GCP_USERNAME }}
          key: ${{ secrets.GCP_SSH_KEY }}
          script: |
            # 서버 내 docker-compose.yml이 있는 경로로 이동
            cd ~/project-root
            
            # GHCR 프라이빗 이미지 접근 (Public 레포면 생략 가능)
            echo ${{ secrets.GHCR_PAT }} | docker login ghcr.io -u ${{ github.actor }} --password-stdin
            
            # 최신 프론트 이미지 Pull 및 컨테이너 재시작
            docker-compose pull capture-frontend
            docker-compose up -d capture-frontend
            docker image prune -f
```

- `${{ secrets.xxxx }}` 형태는 수동으로 등록 해줘야하는 변수
	- *GitHub 레포지토리 > Settings > Secrets and variables > Actions > Repository secrets*
- GHCR_PAT은 e2-micro에서 GHCR에 연결할때 필요한 토큰 
	- *GitHub Settings > Developer settings > Personal access tokens*
- GitHub Actions에서 빌드해서 만든 이미지는 Packages에 있음. 
- 태그를 :latest로 고정하지말고 고유한 해시값을 만들어서 사용하면 버전 관리가 쉬움. 

``` yml
- name: 1. 짧은 커밋 해시 생성
     id: vars
     run: echo "sha_short=$(git rev-parse --short HEAD)" >> $GITHUB_OUTPUT

- name: 2. Docker 이미지 빌드 및 푸시 (태그 2개 부여)
    run: |
	    REPO_LOWER=$(echo "${{ github.repository }}" | tr '[:upper:]' '[:lower:]' )
        SHA=${{ steps.vars.outputs.sha_short }}
          
        # latest 태그와 커밋 해시 태그 두 개를 동시에 빌드/푸시
        docker build -t ghcr.io/$REPO_LOWER/capture-frontend:latest \
                       -t ghcr.io/$REPO_LOWER/capture-frontend:$SHA .
          
        docker push ghcr.io/$REPO_LOWER/capture-frontend:latest
        docker push ghcr.io/$REPO_LOWER/capture-frontend:$SHA

```
